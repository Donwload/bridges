# Логика игры «Мосты»

Этот файл описывает, как устроены данные, генерация, проверка решения,
расширение карты и отрисовка. Главная идея — не пересчитывать одно и то же
повторно: у мостов есть готовые индексы, у карты — кластеры отрисовки,
а расширение карты доказывает единственность решения без полного перебора.

## 1. Файлы

| Файл | Назначение |
| --- | --- |
| `index.html` | Подключает `logic/solution-checker.js`, `logic.js`, `renderer.js`. |
| `logic.js` | Состояние игры, `BridgeStore`, генератор уровня, расширение карты, победа. |
| `logic/solution-checker.js` | Точный солвер и проверка единственности решения. |
| `renderer.js` | Отрисовка через чанки, ввод, анимация, HUD. |
| `tests/logic.test.cjs` | Регрессионные тесты логики и солвера. |

`logic/level-generator.js` — старый неиспользуемый фрагмент. Он не подключён
к странице; актуальный генератор находится в `logic.js`.

## 2. Модель данных

### Острова

`logic.islands` — `Map` вида `"r,c" -> target`, где `target` — число мостов,
которое должно подходить к острову. Допустимый диапазон: `1..8`.

### Мосты и `BridgeStore`

`logic.bridges` — не обычный `Map`, а `BridgeStore extends Map`.
Ключ моста — отсортированная пара координат: `"r1,c1-r2,c2"`.
Значение — кратность моста: 1 или 2.

`BridgeStore` поддерживает два индекса:

- `totals`: суммарное число мостов у каждого острова;
- `edgeMeta`: разобранная геометрия каждого ребра.

Поэтому `getIslandBridgesCount()`, проверка победы и проверка связности
не перебирают все мосты и не разбирают строковые ключи на каждом кадре.
Индексы обновляются в `set`, `delete` и `clear`.

### Кратность моста

Между одной парой островов можно проложить не более двух параллельных
мостов. Двойные связи и делают головоломку интереснее: число на острове
приходится распределять между несколькими рёбрами, а не соединять всё
одиночными мостами.

- `logic.maxBridgeCount` — максимум для текущей игры, всегда не больше `2`;
- по умолчанию `2`;
- даже если в конструкторе запросить больше, значение ограничивается двумя:
  ```js
  const logic = new BridgesGameLogic(9, { maxBridgeCount: 4 });
  // logic.maxBridgeCount === 2
  ```
- клик по ребру увеличивает кратность на 1, а на максимуме — удаляет мост:
  `0 -> 1 -> 2 -> 0`;
- солвер, генератор, проверка победы и отрисовка используют одно и то же
  ограничение.

Число на острове ограничено восемью, поэтому генератор и расширение
подбирают кратности так, чтобы сумма мостов не превышала это значение.

## 3. Солвер

`SolutionChecker.countSolutionsForIslands(islands, maxSolutions, deadline)`
не меняет состояние игры: он работает по снимку карты.

Алгоритм:

1. Строит возможные рёбра по отсортированным строкам и столбцам.
   Соседние острова в таком списке — ровно те, между которыми нет другого
   острова. Это заменяет попарный перебор `O(n²)`.
2. Проверяет связность графа возможных рёбер через DSU. Если граф распался
   на независимые кластеры, решения нет, и полный перебор не запускается.
3. Сортирует рёбра так, чтобы сильнее ограниченные вершины обрабатывались
   раньше.
4. Делает backtracking по кратностям `0..2` с отсечениями:
   - нельзя превысить число острова;
   - оставшейся ёмкости рёбер должно хватать до целевого числа;
   - пересекающиеся мосты запрещены;
   - в конце проверяется связность выбранных мостов.
5. Ёмкость оставшихся рёбер поддерживается инкрементально, а не
   пересчитывается на каждом узле.

Солвер возвращает:

- `1` — ровно одно решение;
- `0` — решений нет;
- `2` и больше — найдено несколько решений (поиск останавливается);
- `-1` — перебор прерван по времени.

## 4. Генерация нового уровня

`generateValidLevel(options)`:

1. Случайно выбирает стартовый остров.
2. На каждом шаге собирает все клетки, которые можно соединить с уже
   поставленными островами по прямой без препятствий.
3. Выбирает кандидатов с **минимальной локальной плотностью**: считает,
   сколько островов уже находится в квадрате 11×11 вокруг кандидата.
   Среди одинаково свободных клеток выбор случайный.
   Поэтому карта не растёт одной длинной веткой, а заполняет свободные
   участки поля.
4. Строит связное дерево мостов через backtracking. Кратность каждого ребра
   выбирается с учётом сложности: одиночный или двойной.
5. Считает числа островов по суммарной кратности рёбер.
6. Отбрасывает карту, если:
   - есть остров с числом 0 или больше 8;
   - сумма чисел нечётная;
   - солвер нашёл не ровно одно решение.

Пока новая карта не принята, текущая карта игрока не изменяется.

## 5. Расширение карты

`expandLevel(options)` вызывается после победы. Старая карта сдвигается
в центр увеличенного поля, старые мосты сохраняются, а новые острова
нужно подключить игроку.

### Почему раньше падал 17-й уровень

Старый алгоритм старался растить новых островов «вынужденные листья»
цепочками во внешней полосе. На высоких уровнях новых островов становилось
слишком много, полоса не успевала дать нужное число вынужденных позиций,
и включался полный солвер на карте из сотен островов. Это могло занять
десятки секунд или закончиться неудачей.

### Новый алгоритм

1. Поле расширяется на чётное число клеток; старые координаты сдвигаются
   на `shift = growth / 2`.
2. Новые острова ставятся в самые свободные клетки:
   - основная часть — во внешнюю полосу;
   - дополнительно проверяется случайная выборка по всей карте, чтобы
     заполнять пустые места и внутри старой области;
   - плотность оценивается по блокам 4×4 (сумма по соседним блокам).
3. Каждый новый остров обязан:
   - иметь ровно одного видимого соседа;
   - получить **уникальные строку и столбец** среди новых островов;
   - не стоять на клетке существующего моста;
   - иметь мост, который не пересекает старые мосты и уже запланированные
     мосты других новых островов.
4. Уникальные строка и столбец означают, что два новых острова не могут
   видеть друг друга: видимость возможна только в одной строке или одном
   столбце. Значит, у каждого нового острова остаётся ровно один старый
   сосед, и его мост — единственное возможное ребро.
5. Кратность моста нового листа выбирается по сложности, но уменьшается,
   если у старого соседа не хватает запаса до 8.
   Например, если у соседа уже 7, новый лист получит 1 мост, а не 2.
6. Число нового острова равно кратности его единственного моста.
   Оно вынуждено: у листа нет другого ребра, куда можно перераспределить
   мосты.

### Доказательство единственности

Пусть старая карта имеет ровно одно решение `S`. Новые острова — листья,
у каждого ровно одно возможное ребро, и число листа равно кратности этого
ребра. Поэтому в любом решении расширенной карты мосты новых листьев
зафиксированы.

Если вычесть эти вынужденные мосты из чисел старых островов, получится
ровно старая задача с её прежними числами. Старая задача имеет единственное
решение `S`, следовательно, расширенная карта тоже имеет ровно одно решение.

Именно поэтому на обычном пути солвер не вызывается: проверка
`forcedByConstruction` подтверждает условие листа, и расширение принимается
сразу. Солвер остаётся только страховкой на случай неожиданного состояния.

### Что это даёт

- Новые острова распределяются по свободным местам, а не растут одной
  прямой цепочкой.
- Нет полного перебора солвера на больших картах.
- 17-й уровень и дальнейшие расширения стабильно создаются за доли секунды
  (замеры зависят от машины и случайной раскладки).
- Старые мосты и уже пройденная часть карты не меняются.

## 6. Проверка победы

`checkVictory()` проверяет:

1. Все числа островов — целые от 1 до 8.
2. Координаты островов находятся внутри поля.
3. Сумма мостов у каждого острова равна его числу.
4. Каждый мост соединяет существующие острова, лежит на одной строке или
   столбце, не проходит через промежуточный остров и не пересекает другие.
5. Кратность каждого моста — от 1 до `maxBridgeCount`.
6. Все острова связаны.

`isConnected()` использует готовые метаданные `BridgeStore`, поэтому не
разбирает ключи повторно.

## 7. Отрисовка

`renderer.js` разбивает мир на чанки 256×256. Есть два статичных слоя:

- слой мостов;
- слой островов.

При изменении моста сбрасываются только чанки, пересекающие его область.
Вода, градиенты и виньетка кэшируются; каждый кадр анимируются только
рябь и блики. Подсветка курсора и выбранного острова рисуется в динамическом
слое и не пересобирает спрайты островов.

Для двойного моста две дорожки раскладываются симметрично относительно
оси:

```text
1 мост:        0
2 моста:  -11, +11
```

Между дорожками рисуется тёмный просвет. Радиус попадания мыши учитывает
смещение крайней дорожки, чтобы двойной мост было удобно выбирать кликом.

## 8. Тесты

Из папки `bridges`:

```powershell
node --test tests/logic.test.cjs
```

Тесты покрывают:

- создание и удаление мостов кратности 1..2;
- жёсткое ограничение `maxBridgeCount` двумя мостами;
- запрет кратности выше максимума;
- победу с двойными мостами;
- солвер с двойными мостами;
- пересечения, промежуточные острова, связность;
- `expandLevel` и сохранение единственности решения;
- неизменность состояния игры при работе солвера по снимку.

## 9. Быстрая диагностика

Если расширение не удалось:

1. Проверьте, что `logic.bridges` содержит решение текущей карты
   (в игре это происходит после победы).
2. Убедитесь, что `maxBridgeCount` одинаков для логики и отрисовки.
3. Запустите тесты.
4. Для отладки можно временно увеличить `maxAttempts` в вызове
   `expandLevel` — это даст алгоритму больше попыток размещения.
